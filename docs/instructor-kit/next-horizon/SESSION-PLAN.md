# Facilitation plan

Use three 60-minute sessions or select one coherent route. Learners should know multiplication, ratios and functions. The training route benefits from derivatives and basic probability; use the mathematical-foundations experience first when needed. The device route introduces capacitance and current explicitly rather than assuming semiconductor expertise.

| Session | Minutes | Activity and evidence |
| --- | --- | --- |
| Data becomes a learned function | 0–10 | Name axes, probabilities and train/development/final roles. Record a prediction. |
| | 10–25 | D1–D2: duplicate families, byte merges, shifted targets and sequence boundaries. Save the manifest. |
| | 25–45 | L1–L2: inspect one update, train the bounded model, fork one objective and inspect forgetting. |
| | 45–60 | G1: failed rank and one committed update. Independently compute the hand weighted mean. |
| A model becomes a working service | 0–15 | S1: identify the source checkpoint and per-request state. Account for cache release. |
| | 15–35 | A1: compare retrieval, support, authority and task result; inspect a durable retry. |
| | 35–50 | E1 and C1: denominator changes and a program that passes examples but violates its contract. |
| | 50–60 | Explain a three-boundary transfer, retaining the original prediction. |
| Matter and control constrain useful work | 0–20 | P1: one electrical specimen, independent gates and load-dependent transition. |
| | 20–35 | H1: corruption, declared code guarantees and rollback. |
| | 35–50 | F1 or R1: baseline comparison, unavailable future data, feedback delay and deadlines. |
| | 50–60 | Trace a failed acceptance condition to the artifact that caused it. |

Reading, labeled tables and keyboard controls are the primary task path; 3D is optional orientation. Let one participant navigate while another explains, then swap roles. For a screen-reader or projected session, supply the record and text equation descriptions before the activity. Allow additional time and do not score pointer speed. A desktop narrow-viewport check does not replace physical iOS/Android or assistive-technology observation.

For an actual observation, use the parent kit's blank observation template. Record device/browser, build, task, assistance, interruptions and what was directly observed. Do not fill outcomes in advance. No human session is reported by this package.
