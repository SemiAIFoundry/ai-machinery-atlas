# Distributed gradients from one causal decoder

`distributed-causal-gradient-2`, portable schema 1. The browser uses real gradients of the existing 423-parameter decoder. Rank actors, retries and the commit barrier are an authored bounded protocol in one JavaScript process; no network timing or production fault-tolerance claim is made.

## Integration

Default component `src/components/model-lifecycle-distributed.tsx`, `DistributedModelLearning({checkpoint?, onSelect?, onServing?})`. Studio ID `distributed`. The optional checkpoint is a complete `LifecycleRun`; file import also accepts the original lifecycle JSON. Every new distributed branch retains model weights, optimizer moments/counter and RNG. Its four-example batch history remains a separate schema rather than counterfeiting the original two-example training cursor.

Pure module `src/lib/model-lifecycle-distributed.ts` exports `distributedLifecycleVersion`, `distributedLifecycleMetadata`, limits/defaults, `DistributedConfig`, `DistributedTrainingRun`, `RankContribution` and the functions below.

1. `createDistributedTrainingRun(checkpoint?, config?)` then `beginDistributedRound(run, config?)` reserves four actual training examples.
2. `computeRankContribution(run, rank)` returns actual loss/gradient numerators and target/sample denominators. `submitRankContribution(run, contribution)` verifies the current round, weights, assigned examples, attempt and recomputed arithmetic.
3. `failDistributedRank` invalidates any uncommitted contribution; `restartDistributedRank` increments the attempt while retaining the same batch, weights and RNG. Stale attempts and duplicate submissions are rejected.
4. `inspectDistributedReduction` exposes weighted and unweighted means. `centralizedDistributedReference` differentiates the global objective independently of rank reduction.
5. `beginDistributedCollective`, `computeDistributedGradientShard(run, owner)` and `submitDistributedGradientShard` expose an explicit reduce-scatter barrier. `commitDistributedRound` clips the complete owned gradient once, advances only each owner’s Adam/SGD slice, reconstructs every replica and checks the centralized invariant within 1e-9. Existing callers that have not opened an explicit collective execute this same pipeline automatically through `commitDistributedRound`; explicitly opened partial collectives never auto-fill missing owners.
6. `serializeDistributedTrainingRun`, `readDistributedTrainingRun` validate bounded records and imported arithmetic. `importDistributedWorkspace` and `retainDistributedExposure` preserve the independent final-test exposure journal after validation and revision checks. Invalid or stale imports do not change the current record or journal.

## Learnable comparison

For token weighting, each rank contributes the sum of token-loss gradients and its count of included target tokens. The global mean divides the sum of all numerators by all target tokens. For sample weighting, each sequence first contributes its mean token gradient; the denominator is the number of sequences. These are different objectives when target counts differ. Response-only examples each include two targets here, so the objectives coincide in that controlled case.

The default 1+3 partition reserves one short sequence and three long sequences: rank denominators 6 and 24, total 30. Seed 7 at initialization gives loss 2.167709799544095. Actual weighted/centralized maximum gradient difference is 3.47e-17, weight difference 5.55e-17; averaging rank means equally differs by 0.0770144 in one gradient coordinate. These are results of the local numerical model, not distributed-device measurements. Equal rank means can agree when rank denominators are equal; the counterexample is scoped to the displayed unequal batch.

The failure protocol allows a single logical rank to retry at fixed membership. [PyTorch DDP documentation](https://docs.pytorch.org/docs/2.14/generated/torch.nn.parallel.DistributedDataParallel.html) motivates explicit gradient averaging and consistent optimizer updates. [TorchElastic](https://docs.pytorch.org/docs/2.14/elastic/run.html) describes a different real runtime policy: worker-group stop/restart and checkpoint recovery. This lesson does not assert that a failed real collective can simply accept one replacement contribution.

## Validation and limits

Run `node --experimental-strip-types --test scripts/model-lifecycle-distributed.test.mjs`. The 32 passing tests cover every partition and both objective/denominator choices, independent finite differences across all 11 tensor groups, an independently written optimizer reference, stale/duplicate/failure barriers, exact deterministic resume, import corruption and bounded malicious inputs. `npx tsc --noEmit` passed. Reports and source checks are adjacent. Browser, physical-device, assistive-technology and learner/specialist checks are separate and are not asserted here.

Limits: four samples, up to three logical ranks, 24 commits, eight restarts per rank, 100 events per active round, 1.4 million serialized characters. All computation is binary64 JavaScript arithmetic. The source corpus and model remain tiny synthetic tasks. Development feedback is shown; this component never opens final examples. Exposure already recorded in a lifecycle checkpoint or the browser journal persists when importing an older record. Browser storage is a procedural disclosure, not tamper-proof isolation.

The optional `onServing(run: DistributedTrainingRun)` callback forwards a cloned full distributed record through an explicit button after any collecting round has committed. It preserves current numerical weights and the distinct distributed history. Serving accepts it through `distributedCheckpoint`; no lifecycle training cursor is fabricated.


## Executed ownership and collectives (N05 follow-up)

Model version 2 adds `round.collective`. It carries current round/attempt identity, nullable owned gradient shards, updated owner optimizer slices and actual per-rank gradient/weight replicas. Portable schema remains 1 with strict model-version compatibility; a version-1 candidate distributed record is explicitly rejected. Original lifecycle checkpoints still import, and the existing create/begin/compute/submit/commit and `onServing` interfaces are unchanged. Factory checkpoint sizes must be recomputed from the actual serialized record; contribution JSON fields are unchanged.

`distributedShardOwners(2)` yields rank 0 parameters [0,212) and rank 1 [212,423); each logical block has 212 slots, so rank 1 pads one zero. Three ranks each own 141 real parameters without padding. `computeDistributedGradientShard` sums the actual current rank numerator slices into their declared owner, then divides by the global target/sample count, never the shard length. `reconstructDistributedShards` validates unique complete ownership, range, round/attempt and optimizer-step identity before assembling parameters in rank order. Missing/duplicate/stale ownership prevents reconstruction.

The complete reduced gradient supplies one shared clipping multiplier. Each owner reads and updates only its local weight/moment/square slice with the retained optimizer step. Actual reduced gradient slices and updated weight slices are gathered onto every replica; the canonical full optimizer snapshot is also assembled for portable checkpointing. A separate full-batch differentiation and independently written optimizer reference verify the result. This is a logical educational combination of reduce-scatter, optimizer state ownership and all-gather. It is not an execution of DDP, ZeRO, NCCL, CUDA or a production communication topology.

`inspectDistributedCollective` exposes owner ranges, status, per-copy numeric payloads, zero padding, logical byte counts and logical optimizer/weight ownership. The direct-copy ledger has three phases: reduce-scatter, gradient all-gather for inspection, and updated-weight all-gather. Each remote copy uses eight bytes per padded binary64 slot. With two ranks, each phase is 3,392 logical bytes, totaling 10,176. With three ranks, each phase is 6,768 bytes, totaling 20,304. Those counts deliberately include a diagnostic gradient all-gather; they are neither a lower bound nor an efficient vendor algorithm. Metadata, denominator synchronization, scalar clipping reduction, real transport framing and hardware latency are outside this payload ledger.

The logical retained moment/square ownership totals 846 scalars across owners; model replicas contain 423 weights each. Full source, pre-update and diagnostic vectors remain in browser memory, so these are not measured heap savings. Failure invalidates all in-flight owned shards before retry; new batches release the previous round's rank/shard payloads while retaining the committed optimizer. The immutable earlier record remains available to callers that explicitly keep it. Moment ownership, payload copies and retained diagnostic state are distinct boundaries.

The [NCCL collective documentation](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/usage/collectives.html), checked by AI agent `/root/curriculum_assessment` on 2026-09-07 (rendered version 2.31.2), specifies consistent collective counts/types, rank-indexed blocks and ordered gathered results. These motivate explicit padding and ownership here. Its production execution and failure semantics are not imported into this browser protocol.
