## Predefined critical conditions

A single reproducible critical defect blocks promotion of the affected pilot until fixed and retested. A participant's initial wrong prediction by itself is not a product defect; use the trace, interface and follow-up explanation to distinguish conceptual uncertainty from misleading behavior.

1. **Wrong scientific result or constraint:** inconsistent units, arithmetic/mask/material transform, double-counted resource boundaries, missing inventory shown as conserved feasible state, or a positive deployable rate despite failed required constraints.
2. **Misleading transfer between scales:** the interface causes or leaves uncorrected an interpretation that a correct ideal sum proves physical timing, synthetic route presets prove vendor superiority/qualification, or the toy readout/resource throughput proves general AI quality. A reviewer-confirmed misleading claim is critical even before a second participant repeats it.
3. **Essential access failure:** a user on a required setup cannot inspect the consequential state, set an essential input, complete the reasoning task, or recover from an optional resource failure through the supported accessible path.
4. **Loss or misattribution of learning work:** an original first attempt is silently replaced, another history is presented as the learner's first, written responses leak into an inputs-only share link, or invalid import partially corrupts current state.
5. **Unreproducible promoted result:** input/model/content identity cannot be recovered sufficiently to reconstruct a consequential result, or a stale share/export is silently evaluated under incompatible semantics.

For less severe findings, record frequency, impact, owner, fix/retest plan and any user-facing scope limit. Do not use “participants could attempt the task” as an exit criterion. Require actual essential-task completion on required access/device paths and recorded explanation/transfer evidence, while avoiding an arbitrary learning-score cutoff for this small formative sample.

## Retest and reporting rules

- Every critical fix gets a focused reproduction test on the corrected build and the affected device/access method. Scientific changes require reviewed expected values and any affected saved-work/version behavior to be rechecked.
- If a comprehension failure led to a content/interaction change, observe an unfamiliar transfer case after revision. Prefer at least one fresh intended learner for the affected task; when only previously coached participants are available, retain that limitation and keep the fresh-observation gap explicit.
- Keep original and revised attempt evidence separate. Do not erase an initial failure when the person succeeds after help. A session containing guidance can still inform design, but report the guidance.
- Write the release evidence statement around actual scope: what was tested, by whom/in what role, which build, which devices/tasks, what failed, what changed, and what remains unknown. Do not infer statistical learning gain, production silicon qualification, universal accessibility or a general application benchmark.

## Fixture preparation record

The accompanying generator validates 38 complete nested documents against the current app parser: 31 task stages, four D/Q storage states, and three explicitly synthetic history records. It recomputes quantitative expectations and checks arithmetic, probability normalization, byte conservation, and suppression of rates for infeasible execution. The generated file contains the actual calculation-source digests.

The facilitator key has been reconciled with the current distinction between a static memory fit and room for the next KV append. In particular, host/HBF weight overflow does not by itself create append headroom when the fixed policy fills HBM. C3 includes a further reduction to 8-bit weight storage to demonstrate complete workload-only recovery on the same four-die package, with no inferred accuracy guarantee.

This is preparation and regression evidence, not specialist approval, completed UI import preservation, physical-device QA, or a learner session. No G0–G7 aggregate gate is marked complete by these checks. If calculation sources change, regenerate the fixtures and revise the card/key before using that candidate.
