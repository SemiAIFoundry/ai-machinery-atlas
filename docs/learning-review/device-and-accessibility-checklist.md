# Physical-device and accessible-task checks

Prepared 7 September 2026. **All checks start `not_run`.** This is an atlas-specific review procedure aligned with approved R08–R10, R13 and R17. It is not a completed WCAG audit or a conformance claim. Preliminary checks cannot establish full accessibility; evaluate complete processes as well as controls. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [WAI Easy Checks](https://www.w3.org/WAI/test-evaluate/preliminary/).

Record each check as `pass`, `fail`, `blocked`, `not_run`, or `not_applicable_with_reason`; attach device/build identity, observed behavior and evidence locator. Do not mark a check passed because an automated scan, desktop emulation or code review suggests it should work. A missing device remains an explicit evidence gap.

## Required environments

| Environment | Record | Complete tasks |
|---|---|---|
| Physical iPhone or iPad, Safari | Hardware, iOS/iPadOS and Safari version, viewport, zoom, orientation, network | One A, B and C task; export/import/share; touch and VoiceOver paths |
| Physical Android phone/tablet, Chrome | Hardware, Android and Chrome version, viewport, font/display scaling, network | One A, B and C task; export/import/share; touch and TalkBack paths |
| Desktop keyboard only | OS/browser/version, viewport, zoom, input setup | All three investigations, prerequisite navigation, data restoration, dialog/failure recovery |
| Desktop screen reader | OS/browser/screen reader and versions; user's usual setup where available | One A, B and C task; table/equation reading; saved-work recovery |

Use at least one physical device in each mobile OS family; report this limited coverage accurately. If practical, include a less powerful device already available rather than substituting a flagship for all mobile risk. Do not acquire devices or contact participants as part of preparing this kit. A trained reviewer can test screen-reader behavior; observation with experienced assistive-technology users adds distinct evidence and should be labeled accordingly.

## Checks

| ID | Procedure and essential outcome | Evidence to retain |
|---|---|---|
| K01 | Start at the atlas entry using keyboard only. Find an investigation, its model assumptions and a prerequisite lesson, then return through app/browser navigation. Current case and relevant inputs remain identifiable; focus follows a meaningful sequence. | Route sequence, keys used, focus destination after return. |
| K02 | Select all case tabs and stage controls; change a slider to a specified value; use route/query selectors, HBF checkbox and text areas, and apply a rising clock edge in “Hold a bit.” All required operations work without pointer dragging, with visible focus and correct labels/current values. | Controls attempted, unreachable or ambiguous controls, focus screenshots. |
| K03 | Open any lesson/dialog/3D overlay used by the path; close it and resume. Tab/Shift+Tab do not strand focus; Escape/close behavior and focus return are appropriate to that surface. Repeat while a lazy resource fails. | Exact trap/loss sequence and recovery, if any. |
| S01 | With VoiceOver, TalkBack and the recorded desktop combination, navigate by headings/controls. Identify active case/stage, route, voltage/load units, integer inputs, context/batch and synthetic assumptions. | Spoken name/role/value excerpts and missing or duplicated labels. |
| S02 | Perform A3 without relying on color or spatial position. Read carry headers, bit order, values and the fifth bit. Inspect the MAC terms and distinguish them from charging energy. Mathematical meaning must survive the spoken/text path. Perform the supplemental D/Q check: changing A changes D, but Q changes only at a clock edge; the text path identifies both Q and edge count. | Exact read order and whether headers/units are available in context. |
| S03 | Perform B2 using the nonvisual/text equivalent. Identify DRAM/base/interface materials, current route and step, height/capacity and compatibility. The accessible explanation must express the same consequential state as the visual route. | Scenario and stage plus both textual quantities and corresponding visual evidence. |
| S04 | Perform C1 and C3. Read masked attention entries separately from readout probabilities; locate unplaced weights/KV and the reason a rate is withheld. A table must not announce a plausible partial inventory as the entire feasible workload. | Announced table names/headers, failed-state explanation and result labels. |
| S05 | Save, import an invalid file, and trigger a failed share/copy path. Status/error messages are discoverable without moving focus unpredictably. A rapid slider change must not drown the essential result in repeated announcements. | Message text, announcement timing and focus behavior. |
| M01 | On each physical mobile device, use portrait and landscape. Change a control near page edges; scroll beside the scene; operate stage buttons without accidental scene dragging. Rotation preserves the scenario and does not lock an ordinary reading task to one orientation. | Device/orientation and accidental gesture or control failures. |
| M02 | Enter a multi-paragraph explanation with the software keyboard, edit in the middle, save and dismiss the keyboard. Prompt, text insertion point and save action remain reachable; no important control is obscured. | Keyboard-open screenshot and resulting saved text comparison. |
| M03 | Export a file through the actual mobile browser/file workflow, find it, reimport it, then open a shared-input link in a separate review context. Clipboard denial/unavailability offers an honest usable alternative. No unrequested answer text enters the share URL. | Filename/location, restored scenario identity and clipboard result. |
| V01 | Resize text to 200%; separately test reflow at 320 CSS px equivalent, including a desktop 400% zoom setup with a 1280 CSS px initial width where available. Read prompts, enter answers, find errors and compare metrics. Essential 2D tables/diagrams may scroll within their own region; ordinary surrounding text stays readable. | CSS viewport/zoom method, screenshots and any exception rationale. |
| V02 | Increase text spacing and device text scaling; inspect focus, high-contrast/forced-color settings where available, and control states without color. Critical text meets applicable contrast requirements; labels, current selection and failure states remain distinguishable. | Settings, measured contrast where assessed, clipped/hidden information. |
| V03 | Inspect adjacent touch targets and controls requiring drag. Assess WCAG's 24 CSS px target-size minimum or applicable spacing/other exceptions; verify a non-drag method for essential state changes. | Measured dimensions/spacing and the exact applicable exception, if used. |
| R01 | Enable reduced motion before entry and while open. Turn off/pause motion using available controls. Inspect the same scientific state without forced animation, continuous rotation or a timing-dependent reveal. | OS/browser preference, behavior before/after, usable static state. |
| R02 | In a controlled QA environment deny WebGL or force a context/resource failure. Complete A3, B2 and C1/C3 using the surviving diagram/text/table path. The page and saved work remain usable; an error names the failed optional resource and provides recovery. | Failure method, task evidence, recovery path; identify simulated failure versus real device failure. |
| R03 | On a recorded constrained network, load readable entry before optional 3D; then enter each investigation and request 3D. Loading feedback is visible; slow/failed optional resources do not block reading, controls or saved work. | Network method/profile, cold/warm cache, resource waterfall and observed completion. |
| R04 | Navigate A → B → C and diagram → 3D → diagram ten times in a dedicated QA session; background and restore the tab. Check input preservation, stuck loaders, console failures and sustained hidden animation/resource accumulation. | Browser instrumentation and before/after resource counts where available; absence of instrumentation is not a measured memory pass. |
| D01 | Save first attempt F and practice P. Reload; switch cases and return; import an inputs-only scenario; open its share link; import conflicting history G. Existing F must remain recoverable and identifiable, P must not silently disappear, and any conflict handling must be explicit. | Before/after exports and exact workflow. Use disposable review records, not personal learning history. |
| D02 | Import malformed JSON, an unknown version, array-valued case ID, mismatched content/check versions, unknown/missing scenario fields, nonfinite/out-of-range and fractional integer controls, oversized text/file, and invalid attempt text/date/scenario metadata. Reject before applying partial state; retain current scenario and work; provide an intelligible error. | Fixture ID, error, unchanged-state comparison. Use existing validation tooling or temporary QA fixtures. |
| D03 | Test storage unavailable/full and app reload without assuming persistence. The interface truthfully reports failure and offers export; an export contains intended inputs/answers/versions. | Failure method and file contents. This checks failure behavior, not an offline-service promise. |

The keyboard requirements above draw on [WAI's keyboard guidance](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html); programmatic controls should expose meaningful names, roles and values as described in [WAI's name/role/value guidance](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html). For the reflow exception and target-size details use [WAI reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) and [WAI target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). These explain criteria; the normative WCAG recommendation governs a conformance assessment.

## Scientific representation checks alongside device QA

Run these on the frozen build with the domain reviewer; accessibility testing does not establish scientific correctness.

- **A:** At the same voltage/load/bit inputs, all representations and accessible equivalents agree on current direction, stored/supply energy, timing boundary, carries and MAC terms. The implemented RC plot shares the reference/current time axis; the functional D/Q stage preserves Q until a rising edge and exports its state. Camera movement does not change a numerical result. Do not substitute a generic MOS geometry for a demonstrated timed complete adder.
- **B:** Compare corresponding states for TC-NCF, MR-MUF and hybrid. Film/micro-bumps, reflow/molded underfill and direct copper/dielectric bonding stay distinct. TSVs remain silicon-through interconnects; a generic copper damascene sequence must not stand for every route. Each control changes only its declared material/geometry/measurement state. Check the [shipped process definitions](../../src/lib/data/process-mechanisms.json) and [review guidance](reviewer-guidance.md), including known-good/test and qualification boundaries.
- **C:** Query, mask, values, weighted sum and readout agree across views; the 70B resource scenario stays explicitly separate. Residency includes unplaced bytes and workspace; failed geometry, current placement, or next-KV append headroom suppresses deployable rates. A static inventory fit must not be presented as a runnable step when the fixed-residency append exceeds capacity. Shared die count/capacity persists across B/C. A fixed snapshot does not imply multi-step generation, training, commissioning or a real application-quality benchmark.

## Performance record

Use the same local gzip method as the baseline for R09's entry target of ≤350 kB; state exactly which eager assets are counted. Record physical-device cold/warm loads and conditions, including any unavailable measurements. Keep controlled timings separate from the roadmap's proposed field LCP/INP/CLS targets. A few QA runs do not produce a representative field 75th percentile. Attach raw measurements and resource identities before marking delivery gates passed.
