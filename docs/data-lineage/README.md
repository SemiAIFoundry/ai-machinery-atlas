# Corpus lineage → tokenizer → sampled packed batch

N02 constructs an actual small dataset pipeline. Twelve original fictional maintenance documents belong to seven authored source families. Two reference texts are reused from incident-017; mirrors, whitespace/case variants and one near duplicate have explicit IDs. Original prompt/response text remains visible after transformation and exclusion. This is a data construction experiment, not a trained language model or a data-quality benchmark.

## Order and boundaries

1. Shuffle original family IDs or individual document IDs with the declared split seed. Assign floor(60%) of units to training, floor(20%) (at least one) to development and the remainder to evaluation. Membership is decided before transformation. Grouping preserves each known source family; individual-document assignment is the contamination challenge. Group fractions and document fractions differ. The idea of using group-level split units is supported by [GroupShuffleSplit's documentation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html), but this code uses its own declared shuffle and three-way allocation, not that library implementation.
2. Keep verbatim text, collapse whitespace, or collapse whitespace and lowercase. These are explicit potentially lossy transformations. Neither whitespace nor case removal is claimed universally safe.
3. Compare transformed prompt/response pairs exactly and compute contiguous three-word shingle Jaccard overlap. A nonexact score ≥0.5 is flagged as near. Known-family, exact and near evidence can coexist in a pair; the number of flagged pairs is not a sum of independently counted types. Cross-split flags are diagnostics, not measured model performance. Training deduplication retains the first exact pair in original corpus order and records every excluded ID and its retained predecessor. Development/evaluation records remain inspectable. The contamination concern is grounded in the [Lee et al. abstract](https://arxiv.org/abs/2107.06499); no memorization or benchmark number from that paper is transferred to this fixture.
4. Fit byte-pair merges using only retained training prompt and response fields. Four structural IDs are reserved: PAD=0, BOS=1, EOS=2, SEP=3. The 256 possible UTF-8 bytes have fixed content IDs 4–259 before any corpus fitting. Each additional merge gets the next ID, beginning at 260. The algorithm repeatedly chooses the most frequent adjacent pair, breaking ties by left then right numeric ID, and replaces non-overlapping instances left to right. A pair must appear at least twice. Counting overlaps is distinct from applying merges: `aaa` contains two adjacent `aa` occurrences but only one non-overlapping replacement. The iterative pair-merge principle follows [Sennrich et al. §3.2](https://arxiv.org/html/1508.07909v5); this authored variant merges UTF-8 bytes across a whole field, has no word pre-tokenizer and never merges across fields. It is not the paper's character/word segmentation implementation.
5. Encode each prepared document as BOS + prompt + SEP + response + EOS. The merge order is frozen for all splits. Full content-token decoding reconstructs each transformed field byte for byte; individual byte tokens can be fragments of a Unicode character and display hexadecimal bytes. Unpaired Unicode surrogates are rejected. Literal strings such as `<eos>` encode as content and do not inject structural tokens. Response masks are shifted target masks: the SEP input predicts the first response token; the last response input predicts EOS. Prompt tokens remain causal context even when their prediction losses are masked.
6. Sample only eligible training documents by seed and a global document cursor. Each epoch uses a fresh deterministic shuffle without replacement. Sampling across an epoch boundary can revisit a source document; its draw instance ID remains distinct. Changing the underlying data construction changes the meaning of the same cursor, which is why the entire construction manifest is retained.
7. Concatenate sampled encoded documents and slice into 16-, 32- or 64-token input blocks, padding the last block. Attention permits only prior/current positions from the same sampled instance in the same block. A document may cross blocks; its earlier-block context is truncated and its document position IDs continue. Next-token targets remain available just outside the input block, so a boundary does not silently drop a legitimate within-document supervised target. Labels are not future input context. EOS-to-next-document-BOS transitions are never trained. This explicit boundary-mask teaching representation is related to the packed-sequence separation described in [Megatron Bridge 0.3.1](https://docs.nvidia.com/nemo/megatron-bridge/0.3.1/training/packed-sequences.html). No fused variable-length kernel, GPU packing speedup or production pretraining pipeline is reproduced.

At default seed 7, three exact training copies are excluded. At split seed 17, individual-document splitting places `fan7-original` in training and its mirror in evaluation; whole-family splitting has no cross-split flagged pair. These are original fixture outcomes, not universal guarantees about deduplication or grouping. Unrecognized families and semantic duplicates remain limitations of real provenance systems.

## Code and integration

`src/lib/data-lineage.ts` exports:

- `buildDataLineage(input)` → prepared documents, duplicate evidence, tokenizer, encoded documents, sampled instances, packed blocks and manifest.
- `trainByteBpe(fields, mergeBudget)`, `encodeByteBpe`, `decodeByteBpe` and `displayBpeToken`.
- `assignLineageSplits`, `sampleLineageDocuments` and `packLineageBatch`.
- `normalizeLineageInput`, `encodeLineageRecord(input, sourceContent)` and `readLineageRecord(raw)`.

`DataLineageExplorer` is the default export from `src/components/data-lineage-explorer.tsx` and accepts optional `onSelect: (lessonId: string) => void`. Root owns studio navigation/registry integration. The component imports its own CSS and uses the repaired shared PortableExperiment for explicit save/restore/export/recovery.

The UI exposes original text, source-family identity, transformed text, exclusions, pairwise evidence, learned merge counts and applications, actual byte token IDs, target masks, sampled epoch positions, packed block indices and one full attention row. Merely changing the objective mask leaves tokens and sampling unchanged. The manifest records the corpus checksum/version, split assignments, exclusions, normalization, tokenizer fitting IDs and merge order, sampler seed/cursor/draw identities and packed-block checksums. Strict restoration recomputes it before applying inputs. Record size is bounded to 20,000 UTF-8 bytes; current manifests are approximately 4–5 KB. Checksums detect accidental/version mismatches and are not cryptographic signatures, licensing evidence or approval.

A read-only panel imports one actual `model-lifecycle-data.ts` example. The lifecycle decoder retains its separate **fixed nine-token whitespace vocabulary**, context-length contract and existing masks. Nothing in this package changes its tokenizer, weights or dataset. BPE token IDs are not passed to that decoder. The shared lesson is the relationship between sequence boundaries, shifted targets and response-only masking; the vocabularies are different experiments.

## Validation

```
node --experimental-strip-types --test scripts/data-lineage.test.mjs
npx tsc --noEmit
```

Seventeen tests pass. They independently check grouped membership, an actual exact train/evaluation leak, normalization effects, hand-counted Jaccard overlap, first-copy lineage, `abab` and overlapping `aaa` merges, numeric tie rules, field and training-only boundaries, unseen UTF-8 round trips, literal special-token safety, response target counts, epoch permutation/cursor continuation, hand-constructed masked packing, every shifted target across block sizes/objectives, repeated-source instance separation, manifest tampering, strict input/size validation and the unchanged lifecycle vocabulary/mask contract.

Browser and phone QA is root's integration responsibility. No neural objective is evaluated here, so the package does not claim that fewer tokens improve model quality, that flagged contamination changes any measured score, or that displayed storage-slot utilization predicts hardware performance. Source metadata records scoped agent reads, not human scientific review.
